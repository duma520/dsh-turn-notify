========================================================================
 回合通知 dsh-turn-notify  v0.1.3  安装说明（三步）
========================================================================

【这是什么】
每轮对话结束，按结果（完成 / 出错 / 中断 / 截断 …）自动推一条提醒到手机。
跑长任务时不用一直盯屏幕，也不用反复刷新页面。
它自己不存账号、不存凭据，真正发消息的是「通知发送器」。

【第 0 步：确认你在用哪个 profile（必须，最容易踩的坑）】
DSH 的不同 profile 是彼此独立的目录。装错 profile 的表现是：
插件文件都在、界面却永远看不到入口、/api/info 永远 404。

PowerShell 里查当前运行的实例指向哪个 profile：

    Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
      Select-Object ProcessId, CommandLine |
      Where-Object { $_.CommandLine -like '*dsh*' }

输出里出现 \.dsh\profiles\desktop\ 就用 desktop，
出现 \profiles\web\ 就用 web。下面所有路径里的 <profile> 都换成它。

【第 1 步：把包放进本机并登记到 profile】
假设你把本包解压/克隆到了 <插件根目录>\dsh-turn-notify。

编辑 <用户目录>\.dsh\profiles\<profile>\package.json，两处都要加：

    "dependencies": {
      "@duma520/dsh-turn-notify": "link:<插件根目录>/dsh-turn-notify"
    },
    "dsh": {
      "profile": {
        "bundles": [
          "@duma520/dsh-turn-notify"
        ]
      }
    }

【第 2 步：建 node_modules 链接（Windows 用 junction，不需要管理员）】

    New-Item -ItemType Junction `
      -Path   "<用户目录>\.dsh\profiles\<profile>\node_modules\@duma520\dsh-turn-notify" `
      -Target "<插件根目录>\dsh-turn-notify"

【第 3 步：重启 DSH，然后三处验证】
A. 前置：确认「通知发送器」已经能用（设置 → 通知发送器 → 发一条测试通知，
   能收到才继续）。收不到就先修它，本插件的消息全借它的手发出去。

B. 打开 DSH → 设置 → 回合通知（或侧栏的「回合通知」整页），
   顶部看到绿色「已启用」标签，说明它在跑。

C. 点「发一条测试通知」，手机响了 = 整条链路通。

========================================================================
配置与数据在哪
========================================================================
- 数据目录：<用户目录>\.dsh\dsh-turn-notify\
- 三个文件：config.json（配置）/ history.json（最多 200 条）/ log.txt（日志）
- 环境变量 DSH_TURN_NOTIFY_DIR 可改数据目录（回归测试靠它隔离）。
- 「发给谁」默认跟随通知发送器：通知发送器选哪几个账号，这里就发给哪几个。
- 界面所有开关实时保存并持久化，重启不丢。

【卸载】
1. 从 package.json 的 dependencies 与 dsh.profile.bundles 里删掉 @duma520/dsh-turn-notify；
2. 删掉 node_modules\@duma520\dsh-turn-notify 这个 junction；
4. 数据目录：<用户目录>\.dsh\dsh-turn-notify\
3. 重启 DSH。

【开源仓库说明】
本包只含插件本体。作者本机的 scaffold/（开发探针与回归脚本）与
version/（历次备份快照）不在仓库里，因为它们绑定本机路径与本机真实数据。
README 里凡出现 node scaffold/... 的命令，clone 仓库后都跑不了，属正常。
