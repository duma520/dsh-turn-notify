========================================================================
 回合通知 dsh-turn-notify  v0.1.17  安装说明（三步）
========================================================================

【这是什么】
每轮对话结束，按结果（完成 / 出错 / 中断 / 截断 …）自动推一条提醒到手机；
Agent 弹出提问等你回答时也会推一条，并列出全部选项（推荐项打 ⭐）。
跑长任务时不用一直盯屏幕，也不用反复刷新页面。
它自己不存账号、不存凭据，真正发消息的是「通知发送器」。

另有四项「数值变化」通知（v0.1.6 起，默认全关，按需打开）：
DeepSeek 余额变了、本机 Token 累计攒够阈值、WorkBuddy 积分变了，各发一条；
v0.1.9 再加一项「WorkBuddy 积分变化（插件版 · 全部账号）」——一次拿回
dsh-connect-workbuddy 的整张账号表（本机实测 13 个号），按账号 id 记基准、
逐号比差值，通知里能说清「是哪个号掉了多少」；多账号有独立的最小间隔
（默认 2 分钟，与余额的 5 分钟互不影响）。原来的单账号项保留不动。
余额查询先试 DSH 凭据库里的 Key，取不到就退到本机快照，并在通知里
明确写「数据时间不是实时的」——绝不假装是实时值。

v0.1.10 三处改进：
1) 余额不再只报「总额」——每个账号都写「总额 / 充值余额 / 赠金余额」三行，
   并额外点明「变的是：账号1充值-2 元」，方便看出是充值到账还是赠金被扣。
2) 「余额 API Key（可填多个）」卡片：最多填 10 个 DeepSeek Key，填几个就查几个、
   每个账号各列三行。Key 只写进 DSH 凭据库，config.json 里只留名字，
   界面上永远不回显已保存的 Key。
3) 多账号积分不再截断到 8 条，全部账号都列出来；「本回合结算」里的积分
   也从「当前选中那一个号」改成「WorkBuddy 全部账号本回合的变化」。

v0.1.11 一处重写：「本回合结算」改成回合前 → 回合后成对比较
1) 回合**开始那一刻**真的联网采一次（异步发起，不阻塞回合），结束时再采一次，
   正文里是两个真实时刻的对比：`余额（09:00:01 → 09:06:42）：267.61 元 → 264.2 元`。
   之前是拿上一轮记下的旧基准比，中间隔多久、有没有别的程序在扣钱都说不清。
2) 余额三项、WorkBuddy 全部账号积分都写成「前 → 后（差值）」；没变化的号也列
   （显示 ±0），因为「这个号没动」本身也是信息。
3) 单边失败如实写「回合开始时没采到 —— 原因，只列回合后的值」，不编 0、也不因为
   一边失败就放弃整条结算。只在一边出现的账号，另一边写「未采到」（v0.1.12 起；
   早先写「—」，有些字体下看着像一片空白，容易被当成排版坏了）。
4) **代价要清楚**：余额请求和积分上游调用都翻倍（13 个号 → 一轮 26 次）。
   这是「准压过省」的选择，可在界面把「结算含余额 / 结算含积分」关掉，只留 Token
   （Token 是零 IO 的）。

v0.1.13 一处修复：余额假警报（不比较，比「标注一下」更对）
1) 症状：余额通知一会儿说涨 40 元、一会儿说跌 40 元，成对出现；有时还显示
   余额翻倍到 535 元再腰斩。真实余额其实一直没怎么动。
2) 根因一（陈旧快照）：本机 ~/.dsh/dsh-usage/provider-snapshots.json 里存着
   2026-10-18 的旧值 307.84。余额接口偶尔超时/限流一次，探测就降级读这个快照，
   基准被改写成 307.84，下一轮实时值回来又是 239.24 —— 差值 ±68.6 全是假的。
   现在：任一侧是快照就直接判「不可比」，不产出差额、不发通知；快照也不许覆盖
   实时基准（只有完全没有任何基准时才写入）。
3) 根因二（同一把 Key 算两次）：DEEPSEEK_API_KEY 和 DEEPSEEK_BALANCE_API_KEY
   指向同一个 secret 时，两个名字各算一次，余额显示成 2 倍。现在按 Key 值去重。
4) 「本回合结算」遇到快照侧同样判「不可比」，不再给「本回合 -40.23 元」。
5) 老快照文件本身没删（那是 dsh-usage 插件的文件），只是不再参与比较。

v0.1.14 一处调整：涨跌标记从彩色圆点换成箭头
1) ⬆️ 涨 / ⬇️ 跌 / 没变化不加任何标记。IM 通知正文是纯文本，QQ、Telegram 都不支持
   给文字上色，箭头是唯一在所有通道都能显示的做法，而且能跟着文字一起复制。
   （v0.1.12 曾用 🟢/🔴/🟡，按用户要求改成箭头，且 ±0 不再挂符号 —— 那行本来就
   写着「（±0 元）」，再加标记是噪音。）
2) 覆盖范围：余额三项（总额 / 充值 / 赠金）、积分逐账号明细、积分合计行、
   `差值：` 行、结算的 `说明` 行，以及「变的是：」里逐项点名的每一处。
3) 没采到数的那一行**不带箭头**：「没数据」和「±0」是两件完全不同的事，不混用。
4) 顺带修两处观感：只在一边采到的账号，另一边从「—」改成「未采到」；
   结算说明行里 Token 的「1181.37 万 个」多一个空格，改成「1181.37 万个」。

v0.1.15 一处调整：涨跌标记从箭头换成三角
1) 🔺 涨 / 🔻 跌 / 没变化不加任何标记。覆盖范围与 v0.1.14 相同。
2) ⚠️ 这两个三角**都是红色的**（🔺 U+1F53A / 🔻 U+1F53B），颜色本身不区分方向，
   只能靠三角形朝上 / 朝下辨别。这是用户 2026-11-25 明确指定的样式
   （原文：「🔽🔼🔺🔻看看哪个能用，我想换成这种🔺🔻」）。
3) 除了 lib/format.js 的 trendEmoji()，还改了 lib/changes.js 里三处**单独拼的**
   `变化：` 行箭头（buildCreditsPluginCandidate / buildBalanceCandidate /
   buildCreditsCandidate）—— 这三处原先不在 trendEmoji 覆盖范围内，正是通知里
   「变化：0 分（合计基准） → 合计 4.29 分」那一行的来源。
4) 没采到数的那一行仍不带三角：「没数据」和「±0」不混用。
5) 升级后必须重启 DSH 后端（lib/ 是进程内 import），再按 Ctrl+R 刷前端。

v0.1.16 一处修复（看不见的功能变化，但影响别人的界面）

1) 症状你可能没直接遇到过：装了「通知发送器 dsh-notify-sender」之后，它的面板
   变成浏览器默认样式 —— 按钮方角、文字全挤在一行。那个插件连修三个版本都没修好。
2) 真原因在本插件这里，不在它那边。DSH 前端会把所有插件的 client.js **拼成一段
   脚本**执行（中间没有隔离），本插件原来在文件最外层声明了 var CSS_LINES，
   对方外层也声明了同名变量；两个 var 撞名不报错，后执行的**静默覆盖**前者。
   实测是本插件的 52 条 .tn-* 样式把对方 64 条 .ns-* 顶掉了。
3) 现在把 CSS_LINES 和 mergePatch 都挪进插件内部作用域，文件最外层只剩
   window.__ModuleLoader__.load({ 这一条注册调用。**功能与设置完全不变**，
   升级后你的通知内容、触发条件、账号选择都不会动。
4) 升级后同样需要重启 DSH 后端 + Ctrl+R 刷前端。
5) 同版还加了一道自动护栏（scaffold/test_client_toplevel.mjs，随 npm test 一起跑）：
   以后谁再往本插件文件最外层加一条语句，测试会直接报失败，不让这个坑第三次复发。
   这一条对你使用没有任何影响，只是防止将来改坏。

v0.1.17 一处修复：「回合前」那一半一直是空的

1) 症状：打开「本回合结算」后，有一半的通知里余额和积分只写了「回合后」的值，
   前面那句是「回合开始时没采到」。看起来像是网络问题，其实不是。
2) 真原因：DSH 宿主有时**不会把 turn/start 事件送到插件**（实测约一半的回合如此）。
   那次事件是「回合前采样」的唯一触发点，没收到就没人去采，正文只能写「没采到」。
3) 现在做三层兜底：
   - 第一层：turn/start 到了 → 当场采（和以前一样）。
   - 第二层：没到 → 本回合**第一个后续事件**（assistant/message、tool/result、
     step/*，或任何带 usage 的事件）到达时补采。正文会标「（回合开始后补采）」，
     不冒充回合开始那一刻。
   - 第三层：整轮连一个事件都没有 → 用快照里**上一回合结束时**的记录兜底，
     正文写明「（取自上一回合结束时 19:42:49 的记录）」。这个值只用来回算差值，
     不会冒充本回合开始值，也绝不补 0。
4) 顺带修掉一个重复文案：原来会写成「回合开始时没采到（回合开始时没有采到）」，
   括号里又重复一遍；现在统一是「回合开始时没采到 —— <具体原因>」。
5) 补采只在第一层失败时才发生，**正常回合的请求量一点没变**（还是开始结束各一次）。
6) 升级后同样需要重启 DSH 后端 + Ctrl+R 刷前端。
每轮对话的开头和结尾各汇总一次「这一轮用了多少 Token / 余额这一轮掉了多少 /
积分这一轮掉了多少」，单独发一条。三项可各自开关；只勾 Token 时零联网（从宿主
事件里累加），勾了余额或积分则每轮前后各查一次（**不受后台那个 5 分钟最小间隔
约束**——套上去会让短回合的前值永远缺失）。查不到就如实写「没采到 / 都没查到」，
不会补一个 0。

【第 0 步：确认你在用哪个 profile（必须，最容易踩的坑）】
DSH 的不同 profile 是彼此独立的目录。装错 profile 的表现是：
插件文件都在、界面却永远看不到入口、/api/info 永远 404。

PowerShell 里查当前运行的实例指向哪个 profile：

    Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
      Select-Object ProcessId, CommandLine |
      Where-Object { $_.CommandLine -like '*dsh*' }

输出里出现 \.dsh\profiles\desktop\ 就用 desktop，
出现 \profiles\web\ 就用 web。下面所有路径里的 <profile> 都换成它。

【第 1 步：把包放进本机并登记到 profile】
假设你把本包解压/克隆到了 <插件根目录>\dsh-turn-notify。

编辑 <用户目录>\.dsh\profiles\<profile>\package.json，两处都要加：

    "dependencies": {
      "@duma520/dsh-turn-notify": "link:<插件根目录>/dsh-turn-notify"
    },
    "dsh": {
      "profile": {
        "bundles": [
          "@duma520/dsh-turn-notify"
        ]
      }
    }

【第 2 步：建 node_modules 链接（Windows 用 junction，不需要管理员）】

    New-Item -ItemType Junction `
      -Path   "<用户目录>\.dsh\profiles\<profile>\node_modules\@duma520\dsh-turn-notify" `
      -Target "<插件根目录>\dsh-turn-notify"

【第 3 步：重启 DSH，然后三处验证】
A. 前置：确认「通知发送器」已经能用（设置 → 通知发送器 → 发一条测试通知，
   能收到才继续）。收不到就先修它，本插件的消息全借它的手发出去。

B. 打开 DSH → 设置 → 回合通知（或侧栏的「回合通知」整页），
   顶部看到绿色「已启用」标签，说明它在跑。

C. 点「发一条测试通知」，手机响了 = 整条链路通。

========================================================================
配置与数据在哪
========================================================================
- 数据目录：<用户目录>\.dsh\dsh-turn-notify\
- 四个文件：config.json（配置）/ history.json（最多 200 条）/ log.txt（日志）/ snapshot.json（变化通知的基准值，含多账号积分逐号基准，删掉安全：下次当作新基准、不通知）
- 环境变量 DSH_TURN_NOTIFY_DIR 可改数据目录（回归测试靠它隔离）。
- 「发给谁」默认跟随通知发送器：通知发送器选哪几个账号，这里就发给哪几个。
- 界面所有开关实时保存并持久化，重启不丢。

【卸载】
1. 从 package.json 的 dependencies 与 dsh.profile.bundles 里删掉 @duma520/dsh-turn-notify；
2. 删掉 node_modules\@duma520\dsh-turn-notify 这个 junction；
3. 删掉数据目录 <用户目录>\.dsh\dsh-turn-notify\（里面是配置与历史）；
4. 重启 DSH。

【开源仓库说明】
本包只含插件本体。作者本机的 scaffold/（开发探针与回归脚本）与
version/（历次备份快照）不在仓库里，因为它们绑定本机路径与本机真实数据。
README 里凡出现 node scaffold/... 的命令，clone 仓库后都跑不了，属正常。
